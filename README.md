# 群聊转发（测试中）chat_bridge

一个 AstrBot v4 插件：把**指定源群聊的消息自动转发到另一个群聊**。支持文本与图片，规则由管理员配置，数据保存在本机 JSON 文件中。

## 功能

- **实时转发**：源群成员发言后，消息以机器人身份立即推送到目标群
- **一源多目标 / 多源一目标**：一个群可以转发到多个群，也可以多个群转发到同一个群
- **原样转发**：转发内容不带任何前缀或占位；普通文本、图片原样转发
- **合并转发（聊天记录）**：源群里的合并转发消息会以「合并记录」形式转发到目标群，不拆条、不加工
- **防回环**：机器人自己发送的消息不会被再次转发
- **管理员控制**：所有规则命令仅管理员可用（可选 `admin_ids` 兜底）

## 安装

把整个 `chat_bridge` 目录复制到 AstrBot 数据目录的 `data/plugins/` 下，然后在 Dashboard 启用插件（或重启 AstrBot）。

## 使用

规则分两步配置：

**第 1 步：在目标群登记目标（仅管理员）**

```
/转发 注册目标 主群
```

在要接收消息的群里执行，把当前会话登记为转发目标「主群」（备注名可自定义，不填则自动编号）。

**第 2 步：在源群绑定（仅管理员）**

```
/转发 绑定 主群
```

在要转发消息的群里执行，之后该群的所有普通发言都会推送到「主群」。

**其他命令：**

```
/转发 解绑 <备注名>    停止当前群转发到该目标
/转发 列表            查看目标与绑定关系
/转发 清空            清空所有目标与绑定
/转发 帮助            查看本说明
```

## 配置（Dashboard 插件设置）

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| `show_sender` | `false` | 转发普通消息时是否带上原发送者昵称（默认原样，不带前缀） |
| `forward_images` | `true` | 是否转发图片；无法转发时静默跳过 |
| `forward_merged` | `true` | 是否转发合并转发（聊天记录）消息 |
| `admin_ids` | `[]` | 管理员兜底 ID 列表（平台管理员之外额外生效） |

## 设计说明

- **会话标识（UMO）**：通过 `event.unified_msg_origin` 在运行时抓取真实会话 ID，无需手动拼平台/群号，跨平台通用。
- **存储**：规则保存在 `data/plugins/chat_bridge/bridge.json`，JSON 原子写入，损坏自动重建为空规则。
- **合并转发机制**：QQ 收到合并转发时通常只有一条 `Forward(id)` 引用。插件优先通过 OneBot 的 `get_forward_msg` 拉取原记录并用 `send_forward_msg` 原样转发（保持聊天记录形态，不做内容合并）；部分实现支持直接透传 forward id；两者都不可用时静默跳过，不发送任何占位内容。
- **隐私**：转发内容会显示源群发送者昵称（可关闭）。请仅在获得相关群成员同意的情况下使用本插件。

## 开发

核心逻辑位于 `core/`，均为纯 Python（无 astrbot 依赖），可独立测试：

```
python -m pytest tests
ruff check .
```
